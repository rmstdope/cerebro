ah-ybsr — what a row shows when liveness cannot be proven

Every row below is this fleet, as its state files actually read at 20:16 today — so you can hold this page beside the Emacs window and see the difference directly.

The carrier fix (the root going back into argv) is not in question here; it restores every row on its own. This page asks a second, narrower question: when the rule cannot prove a session is ours but its pid is running, what should the row say? That is the case a future wrapper change lands you in — this bug is the discriminator breaking for the second time, by a new route.

Benefit: the day a wrapper breaks the discriminator again, the whole column grows a ? and you can see it at a glance — the defect announces itself instead of hiding behind rows that happen to be right. Cost: a fourth suffix in the State column, beside ■ and ×2; and today, before the carrier is fixed, every row carries it — which is honest, but is also eleven question marks that mean "this fleet's plumbing needs fixing" rather than anything about the agent on that row. Once the carrier is fixed the marks vanish and it becomes a rare sight.
OPTION C — fix the carrier only, and leave this fallback exactly as it is
No mockup, because with the carrier fixed the view looks exactly like THE TRUTH panel above: every session is provable again, so the fallback is never reached and nothing about it is visible. Benefit: the smallest change, and the fallback keeps its one real job — a session started by hand outside the fleet shows up rather than being credited with a stale file it does not own. Cost: the failure mode stays exactly as sharp as it was. The next wrapper that rewrites an argument puts you back on the TODAY panel — Wolverine reading idle mid-build, with a stop flag able to land on it — and this is the second time that has happened by a different route.
