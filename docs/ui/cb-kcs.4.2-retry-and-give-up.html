cb-kcs.4.2 — the surface the navigator approved, 2026-09-01

Two rounds. This file is the specification for what the Ratatui fleet view shows while a start keeps failing, and for the one sentence it says when it stops trying. Where this file and the bead's plan disagree, this file is right. It follows docs/ui/cb-kcs.4.1-standby-and-starts.html, which specified the sessions this view starts, and supersedes that file's section 6: with a backoff in place, not every failure parks a row for good.

1. A refusal parks; a death comes back

There are two ways a start comes to nothing. The launcher refused — exit status 2, which is scripts/launch-preflight's status on all ten of its refusal paths and scripts/launch's for a name already running — and it printed a reason on the way out. Or the session simply died: any other non-zero code, or a start that never became a session at all. A refusal is not going to say anything different in thirty seconds, so its row is honest about nobody coming. A death is retried.

┌ Fleet ─────────────────────────────────────────┐
│  AGENT       STATE       BEAD                  │
│● Beast       plan        cb-kcs.4.2            │
│○ Storm       dead        ✗ refused             │  said why — only s
│◌ Xavier      standby     ↻ retry in 30s, 1 failed  │  died — coming back
│◌ Rogue       standby     → planned              │  nothing wrong
└────────────────────────────────────────────────┘

This is M-x cerebro's own rule (cb-eat), reached there through whether the dying session left a line behind. This view has no line to read — cb-kcs.3 chose the exit code, always — so the two kinds are told apart by the status itself, which is the same distinction stated in the one thing this view can see.

2. The row counts the wait down

The schedule is 0, 30s, 2m, 10m, and 10m for every failure after that. The first retry is immediate: something that failed once should come straight back, and a clock there would cost the fleet a pass every time anything went wrong once. What escalates is the second failure and every one after it. The wait is measured from the failed start itself, so the figure the row counts down and the wait the view enforces are one calculation.

│◌ Xavier      standby     ↻ retry in 45s, 2 failed  │
│◌ Rogue       standby     ↻ retry in 2m, 3 failed   │
│◌ Beast       standby     → buffer<4                │

Blue, and in place of the condition — not the red verdict plus a countdown, which was drawn and declined: it would break cb-kcs.4.1's rule that a row shows a bead, or a verdict, or a condition and never two, and it would put a red cell on a row that is not dead. The count of failed starts is on the row; the exit code is one Tab away on the retained screen. Seconds below a minute, whole minutes above it, rounded up, so a row never names a smaller figure than the wait actually left.

The countdown wins even when the role's own condition is false. A planner backing off in front of a full buffer still reads ↻ retry in 2m, 2 failed rather than → buffer<4. One rule and one source of truth: while a backoff is running the row says so, and a failure is never invisible. The accepted cost is a countdown that reaches zero and visibly does nothing, because nothing was due anyway. Showing the condition instead was declined — two failed starts would be invisible until work arrived, and the cell would flip between two vocabularies as the board moved.

3. After five, the view stops

Five consecutive starts that produced no pass is a fleet that is not going to succeed on the sixth without a person. The name leaves the armed set, the row goes grey, and s is the only way back.

Cerebro — supervising Xavier: 5 starts produced no pass; the view has stopped trying.
┌ Fleet ─────────────────────────────────────────┐
│  AGENT       STATE       BEAD                  │
│○ Xavier      dead        ✗ 5 failed starts     │
└────────────────────────────────────────────────┘

The gold line is said once, in the header's notice slot, cleared by the next keystroke like every notice — the same slot that says Started Beast — buffer 2 of 4., saying the opposite thing. Nothing is said for the individual retries. Naming s in the sentence, and naming the last exit code in it, were both drawn and declined: the header's key hints already name the key, and the code is on the retained screen.

The cell is the count alone. ✗ code 2, 5 failed and Emacs's fuller ✗ code 2, 5 failed starts — press s were declined; the count is what distinguishes this row from every other dead one, and the code is already in the pane.

4. The Session pane is unchanged

A name that gave up is a dead agent like any other, and cb-kcs.3's rule holds without an exception: the pane is the retained screen itself, scrollable, closed by its red exit line and the dim footer. A written report above the footer was drawn and declined — the pane holds terminal output and one kind of thing only.

┌ Xavier — ended 14:32 ────────────────────────────────────┐
│                                                          │
│ Xavier exited with code 137.                             │
│ End of retained scrollback. Up/Down scroll while focused. │
└──────────────────────────────────────────────────────────┘

Accepted, and named rather than discovered: a name that failed five times printing nothing has a nearly empty pane. The grey row, its red ✗ 5 failed starts and the gold line are what account for it.

5. s is the way back, and it starts over

Pressing s on a row that is backing off starts it at once, whatever the countdown said: a start the navigator asked for waits for nothing. It also clears the count, so the schedule begins again from immediate. That is M-x cerebro's own rule — a start with no trigger behind it is the navigator's, and it resets the backoff. k on such a row still means disarm, exactly as cb-kcs.4.1 specified.
