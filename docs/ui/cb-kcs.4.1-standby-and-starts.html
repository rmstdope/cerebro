cb-kcs.4.1 — the surface the navigator approved, 2026-09-01

Three rounds. This file is the specification for how the Ratatui fleet view shows an agent it will start again, and for every sentence it says while starting one. Where this file and the bead's plan disagree, this file is right. It follows docs/ui/cb-kcs.3-lifecycle-from-state.html, which specified the sessions this view ends; this one specifies the ones it starts.

1. A row the view will bring back says what it is waiting for

A standby row is an agent with no session that a trigger will start again. It has no bead and no verdict, so its BEAD column is free, and it spends it on the condition. Two alternatives were drawn and declined: the word standby alone with a whole sentence in the Session pane (a keystroke per agent to learn why any of them is asleep), and the condition in the STATE column instead of the word (STATE stops being a closed vocabulary of state words).

The whole vocabulary, and it is closed

  → buffer<N    a planner: the planned, unclaimed buffer is below N
  → planned     an implementer: a planned, unclaimed bead
  → merged      the verifier: a bead merged and not yet verified
  → unranked    the orchestrator: a bead nobody has ranked

The number stays in the planner's label. → buffer<4 is exactly ten cells, which is BEAD's floor; a ten-implementer fleet wants eleven, and the column takes them — it already sizes itself to its widest cell and only falls back to the floor when the pane cannot spare them. Dropping the number for a label that never grows was declined: the number is the part that changes.

A verdict and a condition never appear on one row. A name whose last session ended abnormally is not restated as standby at all — it stays dead and keeps the red verdict of docs/ui/cb-kcs.3-lifecycle-from-state.html. So a row carries a bead, or a verdict, or a condition, and never two of them.

Only these four roles are armed. The roles whose work arrives from outside the fleet — an issue, somebody else's pull request, a debt sweep — are judged by a reader this view does not have yet. Until it does, they are not armed and their rows read dead: nothing on screen promises a return the view cannot perform, which is the rule the previous bead set for itself.

2. The Session pane of a standby row says standby too

The pane keeps the retained screen of the last pass, exactly as before. Only its title changes, so the row and the pane use one word for one agent. A name this view has never run has no transcript and keeps the ordinary placeholder.

3. Every start is announced, and says why

A start is the fourth thing this view does unattended, after the end, the retire and the nudge the previous bead announced. It takes the same gold notice slot, cleared by the next keystroke like every notice, and two events in one tick means only the second is read — the same cost, accepted again. The reason is the trigger's own phrase, quoted from M-x cerebro so a navigator moving between the two views reads one vocabulary.

Cerebro — supervising | Started Xavier — P0 cb-9zz unplanned. | g refresh | q quit
Cerebro — supervising | Started Beast — buffer 2 of 4. | g refresh | q quit
Cerebro — supervising | Started Rogue — 3 planned, unclaimed. | g refresh | q quit
Cerebro — supervising | Started Psylocke — 2 merged, unverified. | g refresh | q quit
Cerebro — supervising | Started Psylocke — 1 stale verdict. | g refresh | q quit
Cerebro — supervising | Started Cerebro — 4 unranked. | g refresh | q quit

And as the view comes up, one line about both halves of the roster's declaration

Cerebro — supervising | Started Cyclops and Rogue; Xavier, Beast, Psylocke and Cerebro are on standby. | q quit

Both halves, because the declaration did both and only one of them is otherwise audible. It is long, and on a narrow header it shortens the key hints the way any long notice does. Naming only the started agents, and saying nothing at all, were both declined: the second makes an autostart that was refused look like one that never happened.

4. Two rules hold a start back, and neither is visible

Role-start spacing keeps the second planner thirty seconds behind the first, and the unchanged-work guard refuses a trigger that names exactly what this role's own last pass was started for. Neither is a failure and neither shows: the row keeps its condition, and nothing is said. That is what M-x cerebro does, and the only trace either leaves is a log line this crate does not write yet. Marking a held row was drawn and declined — a fifth vocabulary entry and a countdown that redraws every tick, for a state that is normal.

│◌ Xavier      standby     → buffer<4  │
│◌ Beast       standby     → buffer<4  │   held 24s more by spacing — no sign of it

5. k on a standby row disarms it; f means what it always means

There is nothing running to kill, so k stops the view bringing the agent back. The prompt is the one approved with the previous bead, in the shape every kill prompt has, where the second sentence is the consequence the navigator might not have in mind.

Cerebro — supervising | Disarm Xavier? The view will stop bringing it back.  y / n | q quit
Cerebro — supervising | Xavier is disarmed; the view will not bring it back. | g refresh | q quit
│◌ Xavier      standby     → buffer<4  │  before
│○ Xavier      dead                    │  after

f writes the stop flag, on a standby row as on any other, and says Xavier will finish after this pass. The flag is what a start checks before it runs, so a flagged standby name is never started; pressing f again clears the flag it set and says Xavier will keep going. One rule for one key at every state — refusing it here, or making it disarm as well, would give f two meanings and take one from k.

6. A start that fails parks the row, and only s brings it back

Any abnormal exit — a launcher that refused, a session that crashed silently — takes the name out of the armed set, so the row goes grey and keeps its red verdict rather than returning to standby. Nothing retries it. That is deliberately stricter than M-x cerebro, which sends a silent crash back to standby and relies on a backoff to space the retries out; that backoff is the next bead, and without it a silently crashing agent would be relaunched every five seconds.

│◌ Xavier      standby     → buffer<4  │  before
│○ Xavier      dead        ✗ refused   │  after: not armed, not retried

7. A view handing supervision over disarms as it ends

A draining view keeps the sessions it already hosts and starts nothing new. When one of those passes ends, the name leaves the armed set with it, so the row goes grey rather than showing a blue dotted circle this view will never act on.

Cerebro — draining | 1 live agent
│● Cyclops     build       cb-kcs.2.2  │  still hosted here
│○ Rogue       dead                    │  its pass ended: disarmed, not standby
