cb-lz5.1 — Record B: two fields, one per stage

The experience agent writes the bead's notes field and never touches design. The implementation-design agent writes design and never touches notes. Each stage owns one field outright, so neither can overwrite the other even by accident — and design keeps exactly the shape an implementer already reads today.

1. After the experience agent's pass — bd show cb-abc

Two fields, and one of them is empty. bd show prints them in this order.

cb-abc  P2  open   Row limit settable from the list pane
labels: experience:agreed

Design:
  (none)

Notes:

  ## The agreed experience

  The list pane grows a Rows control at the right of its header, showing
  the current limit as a number. Clicking it opens a short menu — 50, 100, 250,
  500, All — and choosing one reloads the list at once. The chosen limit is
  remembered for the next visit.

  Empty list    the control still shows, dimmed, reading `Rows 100'.
  Still loading the control is dimmed and does not open.
  Fewer rows   than the limit: the control reads `Rows 100' unchanged.
  Narrow window the control drops to the line below the title.

  The words, exactly: the control reads Rows; the menu entries read
  50, 100, 250, 500, All; the empty list reads
  Nothing to show yet.

  ## What was considered and rejected

  A number the person types. Rejected: every typed value has to be
  validated and explained, and the four steps cover what anyone wanted.

  Infinite scroll instead of a limit. Rejected: the navigator wants to say
  how much is loaded, and scroll position is not a setting they can state.

  Remembering the limit per data set. Rejected for now: one remembered
  value is what was asked for.

  ## The mockup

  docs/ui/cb-abc-row-limit.html — chosen 2026-09-04, after three rounds.
