cb-kcs.5.4 — the surface the navigator approved, 2026-09-02

Three rounds. This file is the specification for the priority keys the Ratatui Work pane gains, for the cursor that makes every bead reachable, for the History section, and for every sentence the pane says while doing any of it. Where this file and the bead’s plan disagree, this file is right. It refines docs/ui/cb-kcs.5.1-sweeps-section.html in exactly one place — the cursor rule — and changes nothing else any earlier file in the cb-kcs family decided: not a fleet row, not a lifecycle key, not the header’s own title, not the Sweeps section.

1. The cursor: one cursor, over findings and beads alike

↑/↓/PgUp/PgDn always move a cursor when Work has focus, over every sweep finding and every bead row, and the pane scrolls to follow it exactly as Fleet does. They no longer scroll the pane.

┌ Work ────────────────────────────────┐
│Sweeps 2                              │
│  close cb-9su — delivered by Cyclo…  │
│  reclaim cb-mqa — Rogue gone, not …  │
│                                      │
│Claimed 2                             │
│  cb-kcs.4.1  P1 The Ratatui view s…  │
│  cb-mqa      P2 One place answers …  │
│Rows 1–13 of 43                       │
└──────────────────────────────────────┘
┌ Work ────────────────────────────────┐
│Planned, unclaimed 3                  │
│  cb-kcs.4.2  P1 A start that keeps…  │
│  cb-x3u      P2 Reader tests stop …  │
│  cb-9su      P3 Every reader of th…  │
│Rows 5–17 of 43                       │
└──────────────────────────────────────┘

This supersedes cb-kcs.5.1’s “findings are the only rows that can hold a cursor”, and nothing else in that file. The priority keys have to point at a bead, and a second cursor moved by n/p was rejected: it would put two grey rows on screen at once and two ways to move in one pane, and which one a key acted on would be decided by the key rather than by where the eye was.

The cost is accepted: ↑/↓ stop being a scroll, so reaching the bottom of a forty-three row document is a row at a time. PgUp/PgDn still move a viewport’s worth, as a page-jump of the cursor.

The cursor never lands on a row no key can act on, so a grey row always means a key will do something here. History rows are skipped for that reason, even though they are content rather than furniture — nothing acts on one.

Where it starts

┌ Work ────────────────────────────────┐
│Claimed 2                             │
│  cb-kcs.4.1  P1 The Ratatui view s…  │
│  cb-mqa      P2 One place answers …  │

A grey row from the first frame — the first selectable row of the document, as soon as the pane has content, the way the Fleet pane always shows a selection. Waiting for the first ↑/↓ was rejected: a digit pressed before any arrow key would then do nothing, silently, which is the worst answer a key that writes to the board can give.

2. The priority keys

0–4 set a priority outright, + and - move it one step, u puts the last change back. Only while the Work pane has focus.

Cerebro — supervising  cb-kcs.4.2: P1 → P0
┌ Work ────────────────────────────────┐
│Planned, unclaimed 3                  │
│  cb-kcs.4.2  P0 A start that keeps…  │
└──────────────────────────────────────┘

Work focus only, and this is the one key set in the view that is not “from any focus”. x, s, f and k all act from anywhere; a digit is a far more ordinary keystroke than those, and from Fleet focus 3 would silently rerank a bead in a pane nobody was looking at. Acting from any focus was rejected for that alone. A live session holding the keyboard still wins and gets the byte, exactly as it does for x.

No confirmation, and this is deliberately unlike x. The keystroke is the intent: a mis-keyed digit is undone rather than prevented, which is what M-x cerebro does and why u exists. A y/n prompt was rejected because reranking a backlog of twenty beads would become forty keystrokes.

bd dolt push rides the same keypress, which is unlike M-x cerebro — the Emacs panel never pushes a priority change, so it stays on that machine until something else pushes. A ranking other machines cannot see is half done: that is the argument x already won here, and the two board writes in this view now behave alike. Exact parity with Emacs was rejected for that reason.

Clamped, never wrapped: + on a P0 and - on a P4 say is already P0 / is already P4 and write nothing — and a keystroke that did nothing must not leave an undo entry claiming it did.

Every line they can put in the header

cb-kcs.4.2: P1 → P0
cb-kcs.4.2 is already P0
cb-kcs.4.2: back to P1
cb-kcs.4.2: P1 → P0, but bd dolt push failed — other machines will not see this yet
bd would not set cb-kcs.4.2 to P0
nothing to undo

Gold for the four that changed something or found nothing to change, red for the two failures — the split x already uses. Each is cleared by the next keystroke, like every other notice. The success line says where the bead came from; echoing the command (ran bd update cb-kcs.4.2 --priority 0), which is what x does, was rejected here because the previous number is what makes u legible.

u

One step, and only using it spends it. The entry survives a refresh, a g, and the bead scrolling out of view; a second u says nothing to undo. A later priority change overwrites it, so it always describes the most recent one. Clearing it on a refresh or when the bead leaves the pane was rejected: it is a one-step rescue for a mis-keyed digit, and a rescue that expires on a timer is one that is not there when it is reached for.

3. Reaching the beads behind +N more

Every section stops at eight rows. The P4 backlog is the one queue reranking is really for, and it is always longer than eight — so the +N more line takes the cursor, and Enter shows the rest of that section.

┌ Work ────────────────────────────────┐
│Unplanned 23                          │
│  cb-hzs      P4 A stale state file…  │
│  +15 more                            │
└──────────────────────────────────────┘  not under the cursor
┌ Work ────────────────────────────────┐
│Unplanned 23                          │
│  cb-hzs      P4 A stale state file…  │
│  +15 more — Enter                    │
└──────────────────────────────────────┘  under the cursor
┌ Work ────────────────────────────────┐
│Unplanned 23                          │
│  cb-4cn      P2 The header renders…  │
│  … all 23 rows …                     │
│  cb-wxr      P4 A red gate names i…  │
│  all 23 shown — Enter                │
└──────────────────────────────────────┘  open

The key is named only under the cursor. Saying it on every frame was rejected as eight cells of noise on every section that hides anything; never saying it was rejected because nobody would find it.

The last row of an open section is the way back, in the same place the +N more line was, and a section with nothing hidden never has such a row, open or shut. An expanded section stays expanded until Enter closes it or the view exits — it survives the thirty-second work refresh and g. Closing itself on the next refresh was rejected: a rerank of fifteen beads would be interrupted by the section shutting under the cursor.

Removing the cap altogether was rejected: it exists so that the two sections worth reading are not pushed off the bottom by the third, and a twenty-three bead Unplanned queue would do exactly that on every render rather than on the one where it was asked for.

4. History

scripts/fleet-history --summary answers one question: what is each agent doing right now, how long has it been doing it, and is that long by its own standards. One line per open interval, gold when it has run past twice its own median.

┌ Work ────────────────────────────────┐
│Waiting on you 1                      │
│  cb-wfb      P2 Parked beads say h…  │
│                                      │
│Merged, unverified 2                  │
│  cb-kcs.5.1  P1 The Ratatui view r…  │
│  cb-4cn      P2 The header renders…  │
│                                      │
│History 4                             │
│  Beast working 1m                    │
│  Cerebro asking 4m - long, median 1m │
│  Cyclops working 2m                  │
│  Psylocke asking 537m - long, media… │
│Rows 30–43 of 43                      │
└──────────────────────────────────────┘

Last, after Merged, unverified — the M-x cerebro order, so the two views read alike. Putting it first, above Sweeps, was rejected: it would be on screen every day whether or not anything was unusual, and up to ten lines of reassurance would push the two sections that are about work you can act on off the top of the pane. Replacing the section with a gold long on the Fleet row was rejected too — the median would then never be shown, so the judgement could not be checked on screen, and the two views would stop having the same shape.

History 4, with the count, following every other header in this pane; M-x cerebro writes the bare word. The number is how many agents are running something right now.

One line per open interval, and nothing else. The aggregates are what say whether it is unusual, not what the navigator is being told, so a row whose open_min is null has no line. An agent between passes has none either — the script treats waiting as terminal and drops an interval open beyond a day.

Nothing running, and a run that did not answer

┌ Work ────────────────────────────────┐
│Merged, unverified 2                  │
│  cb-4cn      P2 The header renders…  │
└──────────────────────────────────────┘  nothing running: no header, no line
┌ Work ────────────────────────────────┐
│History 4  fleet-history failed       │
│  Beast working 1m                    │
│  Psylocke asking 537m - long, media… │
└──────────────────────────────────────┘  the rows it had stay; the header says so

Nothing running draws nothing at all — no header, no (none) — exactly as Sweeps does and as Emacs does.

A failed run keeps the rows it had and names the script in red beside the header, the shape cb-kcs.5.1 approved for a sweep that did not answer: the word is failed, and it covers a non-zero exit, a timeout and output that is not the JSON it promised. A failure with nothing yet to keep draws no section at all, and this is the one place History differs from Sweeps: Sweeps draws its header on an empty failed run because a clean fleet and an unreadable one would otherwise draw the same blank, and History has no such confusion — nothing running and no answer both mean this section is telling you nothing. Keeping the rows silently, as M-x cerebro does, was rejected: rows minutes or hours old would read as current.

Its own five-minute clock, the cadence Emacs uses, and g forces a run along with everything else.

5. The hint line

Cerebro — supervising | Tab/Shift-Tab pane | ↑/↓/PgUp/PgDn move | s/f/k start·finish·kill | x act | 0-4/+/-/u priority | g refresh | q/Esc/Ctrl-C quit
Cerebro — supervising | … | x act | Enter show all | g refresh | …

0-4/+/-/u priority is shown only while the cursor is on a bead; Enter show all only while it is on a +N more or all N shown row. Both come after x act, and both live in the half that survives the shortening on a narrow terminal, beside the keys that change something.

Both are shown on a read-only view too, where s/f/ k are not. A priority is a write to the shared board rather than to this checkout’s sessions, so like every other bead-panel key it is deliberately outside the supervision lease — a view that may start nothing may still rerank a bead.
