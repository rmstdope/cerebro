cb-d31 — the surface the navigator approved, 2026-09-03

Two rounds. This file is the specification for what Enter does under Fleet focus in cerebro-tui, and for every sentence the header says while doing it. Where this file and the bead’s plan disagree, this file is right. It changes nothing any earlier file in the cb-kcs family decided: not a fleet row, not a lifecycle key, not the Work pane’s own Enter, not the header’s title.

1. The rule

Under Fleet focus, Enter moves focus to the Session pane for the selected agent — but only when that pane is holding something. When it is empty, focus stays on Fleet and the header says so in gold. It is “Tab twice” in one key, and it is the navigator’s own act, not the supervisor’s: it moves focus and nothing else.

nothing — No live session.refuses: gold Rogue has no session, focus stays on Fleet
the read-only explanationrefuses, the same sentence — the pane holds no session
no agent selected at alldoes nothing and says nothing

Rejected: “Enter always goes there, whatever the pane holds”. It is the simpler rule and it was turned down because a navigator walking the roster with ↓ and pressing Enter on each row would be thrown into an empty pane and have to Shift-Tab back on every standby agent. The cost accepted in exchange: Enter is a key whose effect depends on what the row is doing.

The sentence is Rogue has no session — the agent’s name, no full stop, no ASCII dash, in the house style of this pane’s existing refusals (Xavier is already up, Rogue is not running). Gold, like every notice that is news rather than a fault, and transient: the next keystroke clears it. Rejected: Rogue has no session — press s to start one., because the same sentence has to serve a read-only view where s refuses and its hint is not even offered; and Nothing to show for Rogue, which is about the pane rather than the agent. Note the hint: no Enter session clause here, because the key would not act.

A starting session counts too, on the same rule: it is one dim line (Starting Cerebro…) that is about to become a live one, and refusing focus on a pane that will be live within a second is a refusal that ages badly.

5. The header hint

| Enter session, dim, only while Enter would act — so it appears and disappears as the navigator walks the roster.

Cerebro[tui supervises] | Tab/Shift-Tab pane | ↑/↓/PgUp/PgDn move | s/f/k agent | Enter session | g refresh | q quit
Fleet focused, the selected agent has a session

Cerebro[tui supervises] | Tab/Shift-Tab pane | ↑/↓/PgUp/PgDn move | s/f/k agent | g refresh | q quit
Fleet focused, the selected agent has none — the clause is gone

Cerebro[tui supervises] | Tab/Shift-Tab pane | ↑/↓/PgUp/PgDn move | s/f/k agent | 0-4/+/-/u priority | g refresh | q quit
Work focused — unchanged; the Enter clause is Fleet's alone

Exactly the rule x act and the priority keys already follow: a clause is shown only while its key acts on what is under the cursor. It rides with those two in the header’s shortening order, so a narrow terminal drops the movement hints first and keeps this one. It is never shown under Work or Session focus — Work’s own Enter show all is a different key on a different row and is untouched.

6. What does not change

The Emacs view. M-x cerebro keeps RET meaning “focus the detail window”. It has no Session pane to focus, so there is nothing here to mirror; this is a cerebro-tui bead alone, and the navigator said so. Work’s Enter still opens and closes a +N more section. A focused live session still receives Enter as a carriage return like any other key. Tab and Shift-Tab still cycle all three panes in both directions; this key is a shortcut, not a replacement.
