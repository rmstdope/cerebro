cb-kcs.4.3 — the surface the navigator approved, 2026-09-01

Two rounds. This file is the specification for how the Ratatui fleet view shows the three roles whose work arrives from outside the fleet — Moira (user-feedback), Cypher (reviewer) and Forge (architect) — and for every sentence it says while starting one. Where this file and the bead's plan disagree, this file is right. It extends docs/ui/cb-kcs.4.1-standby-and-starts.html, which armed the other four roles and left these three dead until a GitHub reader existed; this bead builds that reader, and this file specifies the two cells and four sentences it adds. Nothing here changes any row cb-kcs.4.1 or cb-kcs.4.2 already specified.

1. A cadence row counts down to its next pass

The four roles cb-kcs.4.1 armed name a condition, because there is no moment at which it becomes true. These three also carry an hourly floor that starts them whatever else is true — what they watch moves outside this fleet, so a floor is what covers what no timestamp the view reads can show. That floor is a moment, so the cell counts down to it.

┌ Fleet ───────────────────────────────┐
│  AGENT       STATE       BEAD        │
│● Beast       plan        cb-kcs.4.3  │
│◌ Xavier      standby     → buffer<4  │
│◌ Rogue       standby     → planned   │
│◌ Moira       standby     → 43m       │
│◌ Cypher      standby     → 8m        │
│◌ Forge       standby     → due       │
└──────────────────────────────────────┘

The vocabulary this bead adds, and it is closed

  → 43m       under an hour to the next pass
  → 21h04     an hour or more, as hours and minutes
  → due       the floor has passed and the start has not happened yet
  → hourly    this view has no end to count from at all
  → 43m gh?   the same countdown, with `gh' not answering (section 2)

A space after the arrow, on every one of them. One spacing rule for the whole BEAD column, so → 43m sits under → buffer<4 and the column reads as one thing. The elisp view's own spelling — →43m, →due, with no space — was rejected: byte-identical cells across the two views were worth less than a column that does not change its spacing rule halfway down. The two views deliberately differ here, and cb-kcs.4.4's log line follows this file. Naming a condition instead (→ issues, → PRs, → hourly for all three) was rejected because the one row where a number is actually useful — is Forge back in a minute or in fifty — would lose it.

→ hourly is the fallback, not an error. A countdown needs the end of the role's last pass; a role this view has no end for has nothing to count from. It names the floor instead. An empty cell was rejected — that is what M-x cerebro draws, and a standby row with a blank cell says nothing at all about why it is asleep. At startup the roster's own standby declaration stamps an end, so the ordinary first frame is → 60m and this cell is rare.

A backoff countdown still wins. cb-kcs.4.2's ↻ retry in 30s, 2 failed comes before the role's own cell for every kind, and that is unchanged: a row that is backing off says so, whatever it would otherwise be waiting for.

2. When gh stops answering

Moira's and Cypher's conditions are read from gh every ten minutes. When that fails — no network, no gh on PATH, a rate limit — the view keeps the last answer it had but must not act on it, so both roles fall back to their hourly floor alone. Forge is unaffected: its trigger reads no gh.

┌ Fleet ───────────────────────────────┐
│  AGENT       STATE       BEAD        │
│◌ Moira       standby     → 43m gh?   │
│◌ Cypher      standby     → 8m gh?    │
│◌ Forge       standby     → due       │
└──────────────────────────────────────┘

On the two rows it affects, in the same blue as the rest of the cell, and nowhere else. The countdown is all that is left of their trigger, and the suffix says that is why. Blue rather than red: nothing is broken — both roles still run hourly — so this is part of what the row is waiting for, not a fault, and red is already this view's colour for a refused launch's verdict. A gold header notice on the first failure was rejected: the notice slot is shared with every start, end and retire, so a start on the same tick overwrites it, and a navigator who was not looking sees only the suffix anyway. Saying nothing at all was rejected — a fleet that has quietly lost half of Moira's trigger would look exactly like a fleet with nothing to do, and the first evidence would be an issue nobody answered for an hour.

No suffix before the first answer. A reader that has not answered yet is not a reader that failed: the cell is a plain countdown until a request actually fails.

3. g re-asks gh

The header hint is unchanged — g refresh — and what changes is what it covers.

Cerebro — supervising | Tab/Shift-Tab pane | ↑/↓/PgUp/PgDn move | s/f/k start·finish·kill | g refresh | q quit

A navigator who sees gh?, fixes their network and presses g gets an answer at once instead of waiting out the ten-minute clock. Leaving gh on its own clock was rejected for exactly that: a suffix that persists for ten minutes after its cause is fixed, with no way to hurry it. A request already in flight is not stacked, so holding g down asks once.

4. The four sentences a start says

cb-kcs.4.1 settled the shape: Started <Name> — <the trigger's own phrase>. These are the four new phrases, verbatim, each already the elisp view's own wording, so the two views stay on one vocabulary and cb-kcs.4.4 logs the same string.

Started Moira — issue #212 moved.
Started Moira — bead cb-3qh moved (issue #58).
Started Cypher — PR #244 moved.
Started Forge — 60m since its last sweep.

The second is the half of Moira's job that has no GitHub timestamp behind it: a status comment owed to an issue because its bead moved — CLAIMED, MERGED, VERIFIED — which never touches the issue's own updatedAt. Forge says sweep where the other two say pass, because that is what its own role file calls the thing it does. An issue comes before a bead in Moira's order, because an issue is a person waiting and a linked bead is the fleet's own bookkeeping.
