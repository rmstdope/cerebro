cb-3tk — three seams for the end-of-pass command

Every option below is shown as the real prose it would produce, against the real files. Nothing here is committed.

What is broken right now

agents/architect.md lines 66 and 203 tell Forge to write:

.claude/cerebro/scripts/agent-state Forge waiting --pid $PPID

scripts/agent-state has required --wake-in with waiting since 2026-08-21 and exits 2 without it. So every Forge sweep since 2026-08-25 has failed to end its own pass; the state file is left at {state: working, phase: daily} and the role never reaches standby by itself.

The finding that shapes the choice

wake_at is written and nothing reads it. The column that used to render it is gone — cerebro--countdown's own docstring says so: "Nothing waits for a wake any more (cb-5yr) — the countdown that is left is a standby role's cadence trigger." The struct slot is parsed and asserted in tests, and no rendering and no decision consults it. Cadence is cerebro-wake-intervals, entirely.

So the number in --wake-in 600 is, today, a number an agent asks for that nothing honours — 26 occurrences of it across seven files.

This is the shape scripts/planner-buffer already has — a rule that was prose in two places, moved into code, held by a contract test.

One small change to one script; the broken file becomes correct without being edited.

A and C together

They combine: end-pass exists to name the act — "this pass is over" — rather than to carry a number, and passes no wake because after C there is none to pass. That reads better than an A on its own, whose script's only extra job would be supplying a figure nobody reads.
