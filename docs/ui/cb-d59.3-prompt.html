cb-d59.3 — the marker moves into the prompt you can see

Today the sentence that proves a session is ours rides on --append-system-prompt: you never see it, it is folded into the system prompt. Copilot has no such flag (measured, M12) and refuses a bare trailing prompt argument (M3) — the prompt must be -i "<one string>". So the marker has to travel inside the opening prompt itself, which is the one argument every CLI accepts.

That prompt is the session's first user message, and you see it in the vterm. So the only thing still to decide is what that first message looks like. The sentence is unchanged either way, which is what keeps every session already running from going dead the moment this merges.
OPTION A — marker first, then the instruction 
> This session is Xavier of the cerebro fleet rooted at /Users/henrikku/repos/cerebro/. This
  sentence is how the fleet view proves the session belongs to this checkout; do not remove it.

  You are Xavier. Your agent definition (planner) is the whole of your instructions: follow it from
  the top, and start now rather than waiting to be spoken to.
The identity leads. It is also ~200 bytes earlier in the command line, which is the margin that matters if anything ever truncates ps output — the liveness rule reads that line.
OPTION B — instruction first, marker last 
> You are Xavier. Your agent definition (planner) is the whole of your instructions: follow it from
  the top, and start now rather than waiting to be spoken to.

  This session is Xavier of the cerebro fleet rooted at /Users/henrikku/repos/cerebro/. This
  sentence is how the fleet view proves the session belongs to this checkout; do not remove it.
Reads the way the session reads today: the instruction is the point, the marker is a footnote. Costs the truncation margin above, and puts the bookkeeping line last, where a long prompt would push it further out.
WHAT CHANGES IN THE COMMAND LINE (either option) 
exec claude --agent planner --name Xavier --remote-control Xavier --model opus --effort high \
            --append-system-prompt "This session is Xavier of the cerebro fleet rooted at /…/cerebro/. …" \
            --settings /…/question-state.settings.json --permission-mode auto \
            "This session is Xavier of the cerebro fleet rooted at /…/cerebro/. …

             You are Xavier. Your agent definition (planner) is…"
--name Xavier stays — it is still Claude Code's own flag, and Copilot has one too. What changes is that it stops being evidence: the rule reads the marker and nothing else, so neither cerebro--session-args-p nor scripts/agent-alive ever learns a second provider exists.
THE WORDING — keep it, or say it as a message to the agent 
KEEP (recommended)
  This session is Xavier of the cerebro fleet rooted at /Users/henrikku/repos/cerebro/. This
  sentence is how the fleet view proves the session belongs to this checkout; do not remove it.

REWORD
  You are Xavier of the cerebro fleet, rooted at /Users/henrikku/repos/cerebro/. Leave this
  line in place: it is how the fleet view knows this session is yours.
Keeping it is not only taste. Every session running right now carries the old sentence on --append-system-prompt, so an unchanged sentence means the new rule already recognises them and nothing goes dead when this merges. A reword makes merge day a flag day: every live agent reads dead until it is restarted.
