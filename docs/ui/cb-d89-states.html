cb-d89 — the states, and the zero-bead third

The states the happy path hides, and the one presentation decision that changes what the numbers mean. Shown against Option B's table; every variant applies to Option A's JSON equally.

1. The zero-bead third is real, and it is a third

Measured, not estimated. Of 9927.2 AIC this fleet has spent in this checkout, 3286.2 — 33.1% — was spent while the agent held no bead. Where it went:

AgentNo-bead AICWhat that is
Cerebro1593.4Triage passes and sweeps. Cerebro holds no bead by design, so all of its spend is here.
Xavier489.8Pass startup, the buffer count, the candidate query — before a planning: label is taken.
Beast432.3The same, plus passes that planned nothing.
Cyclops364.0Claiming, and the stretch after the bead closed.
Storm, Wolverine, Rogue407.0The same again.

Only 7 AIC of 9927 — 0.07% — falls outside any interval at all, so this is genuinely zero-bead work rather than a hole in the join.

Variant 1 — one row, in the table, sorted with the rest
cb-ej2      309.4    3.1%  Xavier
(no bead)  3286.2   33.1%  Cerebro, Xavier, Beast, ...

Impossible to miss, and add over the column is the true total. It also tops the table on most windows, which some would call the honest answer and some would call noise.

Variant 2 — below the rule, never sorted among the beads
cb-ej2      309.4    3.1%  Xavier
--
no bead    3286.2   33.1%  Cerebro, Xavier, Beast, ...

9 beads, 6641.0 AIC on beads, 3286.2 AIC on no bead, 9927.2 AIC in all.

Beads rank against beads; the overhead is stated once and cannot be mistaken for a bead. The cost is that a caller sorting the JSON has to know the row is special.

Variant 3 — not a row at all, only the footer
cb-ej2      309.4    3.1%  Xavier

9 beads, 6641.0 AIC. A further 3286.2 AIC was spent on no bead (33.1% of 9927.2 in all).

Cleanest table. But per-agent overhead is then unaskable in --by-bead, and the biggest single line of spend in the fleet has no row of its own.

2. Two records, two horizons

Cost and bead-attribution come from different files that are pruned differently. On this machine, right now:

~/.copilot/session-store.db     oldest cerebro session   2026-08-26T20:35Z
.cerebro/state/transitions.jsonl  oldest transition      2026-08-25T10:09Z

So --since 30d can only ever answer about the last two days, and a reader that says nothing about that reports a quiet month.

Variant A — always, on stderr, in every mode
fleet-cost: --since 30d asked for 2026-07-29T00:00Z; cost is recorded from 2026-08-26T20:35Z
and beads from 2026-08-25T10:09Z, so this answers for 2026-08-26T20:35Z onward.
Variant B — only when the window is wider than the record

Silent for --since 24h, which is inside both horizons; the line above appears for --since 30d. Quiet when there is nothing to say.

Variant C — a field in the answer, and nothing on stderr
{"window":{"asked":"2026-07-29T00:00Z","answered_from":"2026-08-26T20:35Z",
            "limited_by":"cost"}, "rows":[ ... ]}

Machine-readable, but it changes the top-level shape from an array to an object, which neither neighbour does.

3. Empty, and the edges

a window with no fleet activity in it
$ scripts/fleet-cost --by-bead --since 30m
No cerebro sessions in the last 30m. (Cost is recorded from 2026-08-26T20:35Z.)

Exit 0 — nothing ran, which is an answer, not a failure. Compare the two refusals below, which are exit 1 and say nothing on stdout.

a bead nobody spent anything on
$ scripts/fleet-cost --by-bead --since 7d --bead cb-zzz
cb-zzz — no cost recorded in the last 7d. Either nothing worked on it in that window, or it was
built before 2026-08-26T20:35Z.
an agent that ran twice under one name (the ×N case)
Xavier             9      6    1521.9    489.8   2011.7  (2 sessions overlapped; their cost is merged)

Two live sessions of one name is a documented state in the fleet view. The join is by agent name and time, so their spend cannot be separated — this line says so rather than quietly attributing both to whichever bead one of them held.

no store at all
$ scripts/fleet-cost --by-bead --since 7d
fleet-cost: no session store at /Users/you/.copilot/session-store.db - cost is recorded per
machine, and nothing has run a copilot session on this one.
no transition log
$ scripts/fleet-cost --by-bead --since 7d
fleet-cost: no transition log under /repo/.cerebro/state - cost can be totalled but not attributed
to any bead. Nothing was reported.
