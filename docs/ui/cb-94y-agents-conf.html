cb-94y — agents.conf, the agreed shape

Agreed over three rounds on 2026-09-10. Which tool an agent runs on stops being one declaration for the whole checkout and becomes a per-agent choice, written by hand beside that agent's model and effort, in a file called agents.conf.

The file

This is what ships, filled in, so a checkout that never touches it behaves exactly as it does today.

# What each agent runs on: which tool, which model, how hard it thinks.
#
# One line per agent. The most specific line that names an agent is the one it gets, whole:
# its own name first, then its role, then "default". Anything that line doesn't say is left
# to the tool itself.
#
#     <agent name | role | default>   tool=...  [model=...] [effort=...]
#
# Every line must say its tool. Every start prints the line it used.
# Anything from a # to the end of a line is a comment.

default      tool=claude  model=opus
implementer  tool=claude  model=sonnet
planner      tool=claude  model=opus     effort=high
architect    tool=claude  model=opus     effort=high

And a fleet that has been edited

default      tool=claude   model=opus
implementer  tool=claude   model=sonnet

# one planner on the other tool, to compare them on the same queue
Beast        tool=copilot  model=gpt-5.5  effort=high
Xavier       tool=claude   model=opus     effort=high

# let claude pick its own model here
Psylocke     tool=claude

How a line is chosen

The most specific line that names the agent wins outright. The others are not consulted, and anything the winning line does not say is left to the tool itself.

Two agents of the same role may now be on two different tools at the same time, in the same checkout. That is the whole point of the change.

Every state, and every word

An agent starts

launch: agents.conf ("Beast") -> copilot, gpt-5.5 at high effort

Printed on every start without exception, so a session behaving oddly three days later is traceable to the file nobody remembers editing.

An agent no line names

launch: agents.conf ("default") -> claude, opus

A line that leaves the model out

launch: agents.conf ("Psylocke") -> claude, claude's own model and effort

There is no file at all

launch: no agents.conf - claude picks its own model and effort

A line asks for a tool nobody has heard of

Beast        tool=copilo  model=gpt-5.5
launch: agents.conf ("Beast"): tool=copilo is not a tool I know. Try: claude, copilot.
In the fleet window
Beast  planner  dead  agents.conf ("Beast"): tool=copilo is not a tool I know
That agent does not start and its row carries the reason until the line is fixed. The rest of the fleet is untouched.

A line does not say which tool

Beast        model=fable
launch: agents.conf ("Beast"): no tool. Every line must say one. Try: claude, copilot.

A setting name is misspelt

Beast        tool=claude  modle=fable
launch: agents.conf ("Beast"): modle is not a setting I know. Try: tool, model, effort.

A line names an agent that is not in the fleet

Wolverine    tool=claude  model=sonnet

Nothing at all is said. No session is ever started under that name, so the line never matches and never refuses anything.

A model the tool does not have

launch: agents.conf ("Beast") -> claude, gpt-5.5 at high effort

Started. Only the tool itself can say whether a model exists, and it will, in its own words. Nothing here second-guesses it.

A checkout that still holds the old file

Nothing is said. A models.conf left behind, and the old fleet-wide tool declaration in the project settings, are simply not read.

The rule behind the three refusals

Nothing ever runs on a setting nobody wrote. A line that means something other than what it says stops that agent, where a line that is merely optimistic — a model this tool may not have — starts it and lets the tool answer.
