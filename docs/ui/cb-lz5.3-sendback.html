cb-lz5.3 — sending a piece of work back to the design stage

Sometimes the agreed experience cannot be built as written: it contradicts itself, it leaves out a state the code must have an answer for, or it asks for something the product cannot do. The board side of this is already settled — the agent takes the “design agreed” mark off, writes what it found into the notes, and the piece of work goes quietly back into the design agent's queue. Nobody is flagged and nothing is escalated.

What is open is what happens in the room: does the agent decide that alone, or check with you first? This is the loop between the two agents, and it is the thing a single combined planner never had to have.

The question — who decides to send it back?

Option A — it decides, says what it found, and sends it back

The agent judges buildability the way it judges everything else about the build, and a send-back is not a question for you. It reports in one message and the pass ends.

The cost: a developer who could have answered the question in five seconds (“per pane, obviously”) does not get the chance, and the work waits for a whole design session instead. The agent sending things back too readily is invisible until someone notices the queue bouncing.

Option B — it says what it found and asks you first

The agent presents the contradiction and one question: send it back, or is this something you can settle here? A developer's answer is recorded as theirs, in the plan, and never written into the designer's record.

The cost: a developer can quietly overrule a designer's document without the designer ever seeing it, and the two now disagree — the plan says one thing and the agreed design still says another. If nobody is in the chair, the agent has asked a question nobody answers and has to send it back anyway, a pass later than it could have.

What the send-back looks like from the other end

Whichever you choose, this is what is written on the piece of work, and what the design agent reads out to a designer next time it comes up. That wording is already agreed (“This one came back from the person building it…”). The developer's own words are kept out of the designer's document — they go in the notes, never in the record.

## Sent back to the UX stage

The agreed design says the row limit applies to "the list". The drawing
shows two lists side by side at different limits. One setting or one per
pane are different features and different builds; the plan cannot be
written until that is settled.

Everything else in the record is buildable as written.
Three rules the note follows in either option: it names what is missing rather than what is wrong with the designer; it says what still stands, so the next session amends rather than starts again; and it ends with the question the designer has to answer. Overrule any of those in a sentence.

When it is not the design that is wrong

For contrast, and not a question — this is how the same agent behaves when the design is fine but something else is in the way. A blocker with no plan, or the machinery failing, is not a send-back: nothing goes back to the designer, and the piece of work stays where it is.
