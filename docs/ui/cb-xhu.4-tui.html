cb-xhu.4 — where fleet health goes in cerebro-tui

You chose Option B for the command: a full four-section report. The Work pane is a fixed 40 columns wide in the split layout, and Option B is about 70 columns of table — so the report does not fit where the Sweeps and History sections live. These are the three ways round it. Rendered at true widths against this machine's real logs.

Everything both give, and the largest change of the three — a reader, a section, a key and a second Session-pane tenant. Almost certainly more than one bead.

What is the same in all three

  • scripts/fleet-health is the only place the judgement lives; the view runs it with --json and renders, exactly as it does with fleet-history.
  • Its own five-minute reader, its own in-flight slot, its own clock — History's pattern.
  • A failed run keeps what it had and names the failure in red beside the header (Health 4 fleet-health failed); a first failure draws nothing at all, which is the ordinary state of a machine that has never run the fleet.
  • Outside the supervision lease: it reads logs and decides nothing, so a read-only view shows it.
  • Emacs is not touched. You said M-x cerebro is on its way out.
