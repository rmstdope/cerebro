cb-ccl — a refused launch leaves a trace

What actually happened on 2026-08-26: every refusal was logged to decisions.jsonl as an exit with code 2 — but with last_line: null, because the launcher's line had not been drawn into the vterm buffer when the sentinel ran. With no line, the cb-eat rule (dead + the line, no retry until s) never fired, and every refusal was treated as a silent death and retried on cb-hzs's backoff, 30+ times per agent. After this bead the launcher writes its own refusal to errors.jsonl and the view reads it back when the buffer gave nothing, so the row below (panel 1) is what you would have seen. Panels 2–4 are the questions.

1. A refused launch — the cb-eat row, now reliable (no choice here unless you want to revisit cb-eat)

Agent          Role          State      Bead       Bead/Phase
○ Psylocke       verifier      dead                  ✗ the checkout is 4 commits behind origin/main and has uncommitted…
○ Storm          implementer   dead                  ✗ the checkout is 4 commits behind origin/main and has uncommitted…
◌ Xavier         planner       standby               → buffer < 4

Stays dead until s; nothing retries. errors.jsonl gets, from the launcher itself:

{"event":"error","ts":"2026-08-26T04:51:14Z","context":"launch Storm","message":"the checkout is 4 commits behind origin/main and has uncommitted changes - commit or stash them, then git merge --ff-only origin/main, before starting Storm"}

Q2 — a session that dies with nothing printed at all (claude killed, a crash): today it retries for ever at the 10m ceiling

Option A — give up after the backoff schedule runs out (5 failed starts): the row goes dead and says so

◌ Storm          implementer   standby               ↻ retry in 10m, 4 failed
○ Storm          implementer   dead                  ✗ exited with code 137, 5 failed starts — press s

RET:

Storm is not running.
Its last 5 sessions ended without a pass (last exit code 137) and printed nothing; the view has stopped retrying.
Press s to start it.

errors.jsonl, one line when it gives up:

{"event":"error","ts":"…","context":"start Storm","message":"gave up after 5 failed starts; the last session exited with code 137 and printed nothing"}

Option B — keep retrying for ever (today), row unchanged

◌ Storm          implementer   standby               ↻ retry in 10m, 34 failed

Cost of A: after a transient fault (network gone for an hour during the preflight fetch) every builder needs one s each. Cost of B: a fleet that cannot start bangs on the door for ever, and only the count says so.
