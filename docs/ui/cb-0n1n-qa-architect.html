Option A — the test architecture is a table of levels

What the agent drafts with you, in .cerebro/test-architecture.md. Proposed the same way as the requirements: one question per level.

# Test architecture
Agreed with the navigator 2026-10-19.

## Unit             fleet-view/src/*.rs, #[cfg(test)]
  Belongs here:    pure decisions — parsing, sweeps, what to draw
  Not here:        files, processes, the clock
  Enough is:       every branch of a decision once

## Script           tests/*.sh, in a throwaway project
  Belongs here:    one script's behaviour, end to end
  Not here:        anything already proven at unit level
  Enough is:       each refusal and each success path

## System           tests/system/*.sh
  Belongs here:    one requirement each, named by its number
  Enough is:       every requirement once

Cost: rigid, but every "too much / too little at a level" finding can point at the line it breaks.
