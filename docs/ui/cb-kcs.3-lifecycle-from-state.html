cb-kcs.3 — the surface the navigator approved, 2026-09-01

Three rounds. What follows is the outcome of each, and nothing else: this file is the specification for how the Ratatui fleet view shows a session it ended, retired, nudged, or watched die. Two things it deliberately does not show are named at the bottom.

1. A row that is not running says why, in the BEAD column

In M-x cerebro the reason a session died goes on the row itself, because the fleet is the whole width of the frame. Here the Fleet pane is 40 columns whenever the terminal is 100 or wider, so a sentence cannot fit. The row carries a verdict instead — a class, in about ten columns, in the column a dead agent is not using — and the sentence itself is in the Session pane. Two alternatives were drawn and declined: a second red line under the row (it doubles a failing fleet's height, and 31 characters still names no diagnosis), and nothing on the row at all (a fleet where three things went wrong then looks like a fleet nobody started).

The whole vocabulary, and it is closed

  ✗ refused     the launcher refused to start it — exit status 2
  ✗ code N      any other non-zero status, whether or not it printed anything
  (nothing)     status 0; or you pressed k; or the view ended it on purpose;
                or nobody ever started it

A session that dies with nothing on its screen still gets its code. That is the one place this parts company with M-x cerebro, and deliberately: Emacs shows such a row as ◌ standby ↻ retry in 2m because it is about to try again, and this view has no standby row yet. A blank there would make a crashed agent read exactly like one nobody has ever started, which is the confusion the verdict column exists to end.

2. The Session pane shows the session's own screen, not a report

A dead agent's pane is the retained screen cb-kcs.2.2 already keeps — scrollable, closed by one verdict line and the existing dim footer. The alternative, a written placeholder in M-x cerebro's words, was declined: it puts a second kind of thing in a pane that otherwise shows terminal output, and throws the rest of the screen away.

Nothing was printed

The view ended it on purpose

┌ Cyclops — ended 14:32 ───────────────────────────┐
│  … the agent's last screen …                     │
│                                                  │
│ Cyclops finished its pass; the view ended it.    │
│                                                  │
│ End of retained scrollback. Up/Down scroll …     │
└──────────────────────────────────────────────────┘

The fourth closing sentence. cb-kcs.2.2 writes three — finished with status 0., finished with status N. in red, and was killed by signal 9. in red, which is what k produces. Ending a session on purpose is technically a signal 9 too, so without a fourth sentence a finished pass would close in red saying it was killed. It gets <Name> finished its pass; the view ended it., in the ordinary colour, and the same sentence whether the grace expired or a stop flag retired it — the header notice below already says which. The dim footer is unchanged: no Press s line is added, since the header's key hint already names the key.

3. The three things the view does unattended, it says in the header

Retirement is not a keystroke: an agent writes waiting, thirty seconds pass, and its session ends while the navigator is reading something else. M-x cerebro says nothing at all. This view says all three, in gold, in the notice slot, cleared by the next keystroke like every notice — two in one tick means only the second is read, and that is accepted.

Cerebro — supervising | Cyclops finished its pass and was ended. | g refresh | q quit
Cerebro — supervising | Storm was retired; its stop flag is cleared. | g refresh | q quit
Cerebro — supervising | Cyclops was asked to hand its question back. | g refresh | q quit

The third is the view typing words into a live agent after its question has gone fifteen minutes unanswered. That is the one of the three that changes what an agent does, so it is the one that most needs saying out loud.

4. A retired agent keeps its transcript — every time

M-x cerebro keeps a retired session's buffer as the record of its pass, except for an idle or between-beads implementer, whose buffer it kills on the grounds that there is nothing worth keeping. That exception is not carried over: every retired agent leaves its last screen in the Session pane, whatever state it was retired from. One rule instead of two, and a transcript thrown away is the one thing here that cannot be recovered.

Two things this deliberately does not show

No ◌ standby row. In Emacs that word means the view ended this session and will start a fresh one when its trigger fires. Nothing in this view starts anything on its own yet — that is the next bead — so a standby row would promise something it cannot do. The rows stay dead, and the word arrives with the thing that makes it true.

No retry, no backoff, no countdown. Same reason: a retry is a start.

When the standby row does arrive, k on one means disarm rather than kill — nothing is running to kill — and the approved prompt for it is Disarm Xavier? The view will stop bringing it back. y / n, in the shape the kill prompt already has, where the second sentence is the consequence the navigator might not have in mind.
