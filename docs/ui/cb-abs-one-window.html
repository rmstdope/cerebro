One window onto the fleet

Cerebro showed a navigator their running fleet through two windows: one in a terminal and an older one inside the editor. The editor half is removed completely — the window, both ways of opening it, and the project setting that said which of the two was allowed to drive. Nothing is kept working for anyone who had it.

cb-abs · agreed 2026-09-09

What a navigator can no longer do

  • Open the fleet inside the editor. The command does not exist; the editor answers in its own words and Cerebro says nothing.
  • Open the fleet with the shorter terminal command. It is removed too, with nothing left in its place — only the terminal window's own command remains, under the name it already has.
  • Tell a project which window may drive its fleet. There is one window, so there is nothing to declare. A project that still has that line written down is not read at all, and nothing is said about it, because nothing is wrong.

No signpost, no message, no compatibility. Somebody who had the editor window finds it gone and is told by the release, not by the product.

What the window says it is allowed to do

The title line is the whole of this. It had nine spellings, because there were two kinds of window and a note saying which one drove. Five survive as three.

The lineWhen it is shown
Cerebro — supervisingThis window is driving the fleet. The ordinary case, and almost always what is on screen.
Cerebro — startingThe moment before it takes over, while it is still working out whether it may. Replaces the bare read-only, which used to be every project's ordinary state and is now half a second.
Cerebro — read-only; another window is driving this fleetA second window opened on the same fleet. This one shows everything and drives nothing.
Cerebro — read-only; this window could not take charge of the fleetSomething went wrong claiming the right to drive, and it is not that another window has it. Reads as a pair with the line above: one says somebody else has it, this says nobody could get it.
Cerebro — handoff pendingRemoved, with the waiting-to-let-go behaviour behind it. It existed because a project could change its mind mid-session about which window drove; with one window and no note, nothing can ever say that.
Cerebro — read-onlyRemoved — became starting.

A second window on the same fleet

opened while the first one is driving

┌─ Fleet ─────────────────────────────┐┌─ Session: Xavier ────────────────┐

│ ● Beast     build-design  idle     ││                                  │

Unchanged from today apart from the wording: it shows everything, starts and stops nothing, and keeps the keys that act on the shared list of work, because those work from any machine whether or not this window is driving.

Nothing could take charge

something went wrong, and no other window has it
Cerebro — read-only; this window could not take charge of the fleet ───────
┌─ Fleet ─────────────────────────────┐┌─ Session: Xavier ────────────────┐
│ ● Xavier    ux            working  ││                                  │

Agents already running keep running; nothing new is started, stopped or nudged. As today, the detail of what went wrong goes to the terminal when the window exits, never into the title — a long path in a status line is unreadable at any width.

Starting

the first moment
Cerebro — starting ────────────────────────────────────────────────────────

Held only until it knows; then supervising, or one of the two read-only lines. read-only is now spent only where something is genuinely contested or wrong.

Everything else is untouched

The three panes, their borders and focus, the keys, the mouse, the sections of the work queue, the sweeps, the health report and every notice keep exactly the shape they have today. This piece of work removes a second window and the setting that chose between them; it changes nothing about the window that is left, beyond the four lines above.
