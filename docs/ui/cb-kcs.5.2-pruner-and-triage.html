cb-kcs.5.2 — the surface the navigator approved, 2026-09-02

Three rounds. This file is the specification for what the Ratatui fleet view says about the two unattended jobs cb-kcs.5.2 moves into it: the prune-worktrees.sh --watch child it keeps running beside itself, and the one line it types into an idle Cerebro when unranked beads are waiting for a ranking. Where this file and the bead’s plan disagree, this file is right.

Neither job has a key and neither has a pane. The only place either can appear is the header’s middle slot — the same slot a nudge, a kill confirmation and a start notice already use, cleared by the next keystroke. Nothing here adds a section, a row, a key or a Tab stop, and nothing here changes what any earlier file in the cb-kcs family decided.

1. The prune watcher, on an ordinary day: nothing at all

Cerebro — supervising | Tab/Shift-Tab pane | ↑/↓/PgUp/PgDn move | s/f/k start·finish·kill | g refresh | q/Esc/Ctrl-C quit

Silent, exactly as M-x cerebro is. The watcher starts with the view and is never mentioned; the script’s own account of what it kept and removed is for troubleshooting, not for the ordinary case. A line at startup — Worktree pruning started. — was rejected: it spends the header slot to announce a job that has run under every fleet view for months and needs nothing from the navigator.

2. The prune watcher, when it dies or cannot start

Cerebro — supervising | Worktree pruning stopped: No such file or directory (os error 2) | Tab/Shift-Tab
Cerebro — supervising | Worktree pruning stopped: exit status 2 | Tab/Shift-Tab pane | ↑/↓/PgUp/PgDn move

Red, and it names the cause. A refused start gives the operating system’s own words; a watcher that spawned and then exited gives its exit status. The plain sentence Worktree pruning stopped; retrying. was rejected — it is the same width class and says strictly less, and the cause is the thing that decides what the navigator does next (a missing script is a submodule that was never initialised, an exit status is something else entirely).

Silence was rejected outright. M-x cerebro swallows all of this, and the cost is that worktrees quietly stop being pruned and the navigator finds out from git worktree list weeks later.

The line comes back every ten minutes while it stays broken, and not more often. A watcher that cannot be started at all is retried on every five-second tick, so “once per death” taken literally is a red line every five seconds; and saying it once and never again was rejected too, because a navigator who was not looking during that one keystroke never learns pruning has stopped. Ten minutes is the watcher’s own sweep interval, so the line comes back exactly as often as a sweep would have happened.

3. The triage line

What is typed into Cerebro is unchanged from what it reads today, and is not in question here:

[cerebro] Unranked beads are waiting for a ranking: cb-a1, cb-b2, cb-c3. Triage them with the navigator.

What is new is that the view says so:

Cerebro — supervising | Cerebro was asked to rank 3 unranked beads. | Tab/Shift-Tab pane | ↑/↓/PgUp/PgDn

Gold, in the notice slot, beside the nudge’s own Cyclops was asked to hand its question back. The name comes from the roster, so it is not always the word “Cerebro”. Emacs’s silence was rejected: within this view a line typed into a session already announces itself, and a triage line is exactly as much an instruction as a nudge is.

was told about 3 unranked beads was rejected as saying what happened without saying what it is for, and naming the beads — told about cb-a1, cb-b2 and 1 more — was rejected because the line’s width would then depend on the board and be cut on a narrow terminal; the ids are in the line Cerebro received and in the log either way.

The ten-minute repeats say it too. The same set is re-typed while Cerebro stays idle, because a typed line can be swallowed and Cerebro writes nothing back to say it heard — so a Cerebro that cannot act shows as a row stuck on idle plus a gold line every ten minutes, which is the whole diagnosis, on screen rather than only in the log. Saying it only when the set changes was rejected for exactly that reason.

4. An idle Cerebro this view does not host

Cerebro is idle, unranked beads exist, but the session was started outside this view:
Cerebro — supervising | Tab/Shift-Tab pane | ↑/↓/PgUp/PgDn move | s/f/k start·finish·kill | g refresh | q/Esc/Ctrl-C quit

Nothing is said, nothing is recorded, and nothing is throttled unless the line actually went into a session this view hosts. This is a deliberate divergence from cerebro--triage-tell, which records “told” and writes its log entry even when no buffer took the string — so its ten-minute throttle then holds for a line that never left the building. The view must not claim something it did not do.
