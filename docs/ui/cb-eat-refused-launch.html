cb-eat — Option A: a launch that dies at once disarms the role

Today: s on Cerebro → the row reads ● up for a tick → the launcher refuses (exit 2) → the name is still armed, so the row goes back to ◌ standby and the reason is only in the echo area for five seconds. In A, an abnormal exit of a session this view started takes the name out of the armed set: the row is dead, the last line the session printed sits in the Bead/Phase column, and nothing retries until s.

Cerebro exited (code 2): cerebro: the checkout is 1 commits behind origin/main and has uncommitted changes - commit or stash them, then git merge --ff-only origin/main, before starting Cerebro

Beast is on the same row shape because its own trigger fired at the floor (10 min), was refused the same way, and was disarmed by it — so it stays dead until s. The ✗ marks the line as the session's last words rather than a phase or an elapsed time; the "cerebro: " prefix the script prints is dropped, and the column truncates with an ellipsis at the window edge (the Bead/Phase column is the last one and already takes what is left).

3. After you commit/stash and press s again — the ordinary shape

Agent          Role          State      Bead       Bead/Phase
● Cerebro        orchestrator  sweep                 0m 0m
◌ Beast          planner       standby               → buffer < 4

Beast has to be pressed s too in A — a disarmed name is not woken by its trigger. Cost of A: once the underlying cause is fixed, every role that was refused needs one keypress each. Benefit: nothing keeps banging on a closed door every ten minutes, and a row never says "a trigger will bring me back" when it will not.
