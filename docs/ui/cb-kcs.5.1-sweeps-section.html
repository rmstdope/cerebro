cb-kcs.5.1 — the surface the navigator approved, 2026-09-02

Four rounds. This file is the specification for the Sweeps section the Ratatui fleet view gains, for the cursor that makes it actionable, and for every sentence it says while acting on a finding. Where this file and the bead’s plan disagree, this file is right. It adds a section to the Work pane docs/ui/cb-kcs.2-split-console.html specified and changes nothing any earlier file in the cb-kcs family decided — not a fleet row, not a lifecycle key, not the header’s own title.

1. Where the section sits, and what its header says

Sweeps is drawn first, above Claimed, and its header carries a count like every other section in the pane.

┌ Work ────────────────────────────────┐

│  reclaim cb-mqa — Rogue gone, not …  │

│Claimed 2                             │

│  cb-mqa      P2 One place answers …  │
│                                      │
│Planned, unclaimed 3                  │
│  cb-kcs.4.2  P1 A start that keeps…  │
│Rows 1–14 of 41                       │
└──────────────────────────────────────┘

First, not last. M-x cerebro draws Sweeps after all six queues, in a window the navigator scrolls to the end of. This pane shows fourteen rows of a forty-one row document, and a section below the fold is one nobody presses. The Emacs order was rejected for that reason alone; nothing else about the panel moves.

Sweeps 6, with the count. M-x cerebro writes the bare word Sweeps, and that spelling was rejected: it is invisible at the bottom of an Emacs window and conspicuous directly above Claimed 2. Every header in this pane carries a number, and the two views deliberately differ here.

One line per finding, cut at the pane width, exactly as a bead row is cut. Two lines per finding — the action on one row, the evidence dimmed beneath — was rejected: six findings would then fill the whole pane and push every queue below the fold, so the Work pane would stop being about the work on a day that already went wrong. A summary line opening a full-width modal list was rejected too: it hides the findings behind a keystroke, and the one that matters most is the one nobody would open the list to find.

The gold line is a stranded P0 — an unassign or a recheck whose bead is P0 — and it is the whole of the escalation, the same rule cerebro--sweep-line already follows: the same gold an asking marker uses, no new glyph, no popup, no sound.

2. The cursor

Findings are the only rows that can hold a cursor. The six queues cannot.

┌ Work ────────────────────────────────┐
│Sweeps 6                              │
│  close cb-9su — delivered by Cyclo…  │
│  reclaim cb-mqa — Rogue gone, not …  │
│Rows 1–13 of 43                       │
└──────────────────────────────────────┘  findings: ↑/↓ move the cursor
┌ Work ────────────────────────────────┐
│Claimed 2                             │
│  cb-kcs.4.1  P1 The Ratatui view s…  │
│  cb-mqa      P2 One place answers …  │
│Rows 1–13 of 36                       │
└──────────────────────────────────────┘  none: ↑/↓ scroll, as they do today

↑/↓/PgUp/PgDn move the cursor when there is at least one finding, and scroll otherwise, and the pane scrolls to follow the cursor exactly as Fleet already does. A separate pair of keys for the findings (n/p, which M-x cerebro uses) was rejected: on the ordinary day there are no findings at all, and the pane should then behave exactly as it does today rather than carry two keys that do nothing.

3. x, and the confirmation

x acts on the finding under the Work cursor, from any focus — the rule s, f and k already follow for the Fleet selection. A live session holding the keyboard still wins, and gets the byte.

Cerebro — supervising  run bd reclaim --id cb-mqa --older-than 10m ?  y / n
┌ Work ────────────────────────────────┐
│Sweeps 6                              │
│  reclaim cb-mqa — Rogue gone, not …  │
└──────────────────────────────────────┘

In the header, in gold, and the next key answers it — byte for byte the shape k already has: y runs it, any other key cancels silently and is consumed, so q at this prompt cancels and does not also quit. A block drawn over the Work pane was rejected: one view should have one way of asking a question, and it already has this one.

The seven prompts, verbatim

run bd close <id> --reason <reason> ?  y / n
run bd reclaim --id <id> --older-than 10m ?  y / n
run bd close <id> ?  y / n
run bd unclaim <id> ?  y / n
run bd update <id> --assignee  ?  y / n
run bd set-state <id> verdict=stale --reason verdict formed against a commit main has moved past ?  y / n
unpause <id> — it goes back to the planners for a re-read.  y / n

Six of the seven are the command, and the seventh is not. bd update <id> --remove-label human is the only one that does not say its own consequence — a label coming off does not read as “this bead leaves your queue for the fleet’s” — and the header has one line, so it says the consequence instead of the command. Appending the sentence to the command was rejected (it is cut first, on exactly the terminal where it is needed) and dropping it was rejected (it is the one thing the Emacs view added on purpose).

4. What it says afterwards

ran bd reclaim --id cb-mqa --older-than 10m
ran, but bd dolt push failed — other machines will not see this yet
bd reclaim --id cb-mqa --older-than 10m failed

One gold line in the header, where the confirmation was. The success line echoes the command, as M-x cerebro does: naming the bead and the effect (cb-mqa reclaimed) was rejected because the command is the thing that actually ran and the only thing that can be checked against the board.

The push line does not repeat it, and that is deliberate: the command has just been on screen twice, in the confirmation and in nothing else that matters, and the news in this line is the push. Repeating it took the line to 106 cells, which is cut on every terminal this view is used on.

bd dolt push rides the same keypress and is not confirmed separately: a close or a reclaim the other machines cannot see is half done, and asking twice for one keystroke’s worth of intent is its own kind of noise.

5. When a sweep does not answer

Three of the six sweep scripts git fetch, so a sweep failing is ordinary rather than exceptional. The findings already on screen stay; the header says which script stopped the run.

┌ Work ────────────────────────────────┐
│Sweeps 6  sweep-claims failed          │
│  close cb-9su — delivered by Cyclo…  │
└──────────────────────────────────────┘
┌ Work ────────────────────────────────┐
│Sweeps 0  sweep-claims failed          │
│                                      │
│Claimed 2                             │
└──────────────────────────────────────┘

Exactly one script name is ever shown, never a count and never a list: the run stops at the first script that does not answer, so no later one has been asked. The word is failed — it covers a non-zero exit, a timeout and output that is not the JSON it promised, and the navigator’s next move is the same for all three.

A failed run with nothing to keep still draws the header (the second screen above), and that is the one place this differs from “no findings means no section”. Hiding it was rejected: a clean fleet and a fleet nobody could look at would then draw the same blank, which is the exact confusion this line exists to end.

6. Nothing found, and the hint line

┌ Work ────────────────────────────────┐
│Claimed 2                             │
│  cb-kcs.4.1  P1 The Ratatui view s…  │
└──────────────────────────────────────┘

A successful sweep that found nothing draws no header and no line, unlike the six queues, which say (none). Those describe queues that are normally not empty; an empty Sweeps section is the ordinary result of almost every run, and a pane announcing it every ten minutes is the noise docs/cerebro-sweeps.md warns against.

Cerebro — supervising | Tab/Shift-Tab pane | ↑/↓/PgUp/PgDn move | s/f/k start·finish·kill | x act | g refresh | q/Esc/Ctrl-C quit

x act joins the hint line after the lifecycle keys, and is shown only while there is a finding to act on — so the ordinary day has exactly the hint line it has today. It belongs in the half that survives the shortening on a narrow terminal, beside s/f/k: the keys that change something outlast the keys that move around.

And it is shown on a read-only view too, where s/f/k are not. Acting on a finding writes to the shared board rather than to this checkout’s sessions, so like every other bead-panel key it is deliberately outside the supervision lease — a view that may start nothing may still close a delivered bead.

7. Cadence

The sweeps run on their own ten-minute clock, as they do in Emacs, and g forces a run along with the fleet and work reads. g not touching the sweeps was rejected: after closing a bead by hand, waiting ten minutes to watch a finding disappear is the moment the navigator actually presses g.
