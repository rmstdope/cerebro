## The full local gate was red in every fleet-view system suite, on main as well, while CI was green

**What happened.** `bash tests/gate` failed twice locally, at load averages of 8 to 10 with other fleet sessions building. All 12 existing fleet-view system suites failed, and in the second run the new `tests/fleet-refused.sh` failed with them. Each view's header read `read-only; this window could not take charge of the fleet` for the whole run. Cargo tests, the web console UI and the 66 other bash suites were green. Three experiments located it:
- `scripts/suite-runner tests` **with this bead's suite moved aside** (main's suites only): the same 12 failed.
- Six fleet suites run at once by hand (`refused`, `view-restart`, `keys`, `board`, `rows`, `stale`): all green.
- All 17 `tests/fleet-*.sh` plus `web-console.sh` at once: 11 red.
So the failure grows with how many views start at once. CI on main and on this PR was green, with `tests/fleet-refused.sh` passing in 42 s.

**Why.** Not established. `fleet-view/src/main.rs` (around line 154) reads the lease's endpoint, legacy endpoint, identity and record **once**, when the view starts, each through `scripts/fleet-supervisor` under `readers::COMMAND_TIMEOUT` (5 s). A failed read becomes `None` (`.ok()`), and `acquire` then answers `LockError("cannot locate the supervision lease")` on every later tick. So one slow `fleet-supervisor` exec while many views are starting would leave that view read-only for good. That fits all three experiments, and it fits cb-7jmm's and cb-yq4c's Rust test failing with that exact string. It is not proven: the views were killed, so their exit diagnostic never printed.

**Cost.** About 25 minutes: two full gate runs, one run of main's suites, two parallel experiments, and reading `supervisor.rs`/`main.rs`. It also cost a review finding that asked to send the bead to the navigator.

**Prevent by.** Read the lease's four `fleet-supervisor` answers again on the supervision tick while any of them is missing, instead of only at startup (`main.rs`, the struct built around line 154), and have a read that failed say so on stderr. This is the same fix cb-gkhx's retrospective points toward. Also: I ran the retrospectives grep for "could not take charge" only after diagnosing, which cb-8dha already warned against. Running it at the first local red would have saved most of the 25 minutes.
