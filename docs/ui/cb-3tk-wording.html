2. The paragraph that has to change

This sentence is repeated verbatim in five files (planner, reviewer, verifier, user-feedback, plan-bead) and is about a number that will no longer exist:

--wake-in is what you ask for, and the view owns what you get: the floor between two starts of your role is cerebro-wake-interval, a defcustom the navigator can change while the fleet runs, measured from your last start and not from the number you wrote. That is why the number is not yours to argue about.

Wording 1 — keeps the "not yours to argue about" register

You do not ask for a wake and there is no number to write. The floor between two starts of your role is cerebro-wake-interval, a defcustom the navigator can change while the fleet runs, measured from your last start. Cadence was never yours, and there is no longer anything in this file that pretends otherwise.

Longer by a clause. Says why the number went, which the next reader of this paragraph will want.

Wording 2 — shorter, states the fact and stops

You do not schedule yourself. The floor between two starts of your role is cerebro-wake-interval, a defcustom the navigator can change while the fleet runs, measured from your last start.

Two sentences instead of four. Loses the history — a reader six months from now sees no trace that agents used to ask.

3. end-pass's own messages

The only strings a navigator sees from the new script are its usage line and its two refusals.

A missing or non-numeric pid

All three are scripts/agent-state's own wording with the program name changed, so the two scripts refuse in one voice.

4. The migration edge

After C, --wake-in is gone from agent-state. What should it do when something passes one anyway?

Refuse

agent-state: unknown argument '--wake-in'

Exit 2, like any other unknown argument. A session running prose from before the merge — one whose skill text is already in its context — fails its end-of-pass write once, loudly, and the navigator sees it on the row. Same failure mode as the bug this bead is fixing, but for one session rather than for ever.

Accept and ignore, for one release

agent-state: --wake-in is ignored; the fleet view owns cadence (it will be removed)

Nothing breaks on merge day. Costs a deprecation branch in the script and in its suite, and somebody has to come back and delete it — which is a second bead, or a comment nobody acts on.

The fact that decides it: a session reads the skill and agent files from its own worktree at launch, so prose and script move together for every session started after the merge. Only a session already running across the merge holds the old text — and in this repository those are minutes long.
