cb-44b — a stop-flagged agent in cerebro-tui's State column

Approved over two interview rounds on 2026-09-03. The State cell gains a one-glyph ■ suffix in gold — this view's colour for "not the ordinary case", the colour the ×N session count and the gh? suffix already use. It sits between the dim ? and the gold ×N, which is cerebro--entry's order: ? qualifies the state word, ■ is about the bead in flight, ×N about the sessions running it.

Three states carry it — working, asking and standby. The first two because a bead is in flight for the flag to be waiting on; standby because that is a row this view would otherwise start, so the flag is doing something visible on it. That third state is a deliberate divergence from M-x cerebro, which shows working/asking only and replaces a standby row's BEAD cell with the words ■ told to finish. Here the BEAD cell is left exactly as it was.

The transient gold header notice on f stays, unchanged, in both its spellings ("Cyclops will finish after this pass." and "Cyclops will keep going."): the notice says what just happened and is also the only confirmation that the keystroke landed on the row the navigator meant, where the marker says what is still true. The row carries the marker in the same frame as the notice.

3. The states that carry no marker

asking carries it, and the row stays bold, which is what bold has always meant here. idle, waiting and dead do not: nothing is in flight and nothing is armed, so the glyph would claim something untrue. up — a live session with no state file — and an unrecognised state word do not either: neither row can tell this view whether a bead is in flight, and the glyph's whole meaning is that the flag took effect while one is still running. The marker is truthful rather than complete.

There is no row-level treatment beyond the glyph. Bold is spent on exactly one state (asking) so that it keeps meaning that, and dim already means dead; a third row-level signal would make the row itself the message across eighteen rows.

5. A flagged standby row that is also backing off

┌─ Fleet ────────────────────────────────────────┐
│  AGENT        STATE       BEAD                 │

Storm's cell counts down to a retry the flag guarantees will not happen, and it keeps counting. The countdown is the state of the backoff and the glyph is the state of the flag: both are true, and the glyph is what says the countdown is moot. Replacing the cell would have hidden how many starts had failed.

The marker is drawn on a view that may supervise nothing. The flag is a fact about the fleet, written to a file both views read, and it is true whoever set it; f still refuses here, so the marker is a thing to read rather than a thing to press. It joins x, the priority keys and Enter in being outside the supervision lease.
