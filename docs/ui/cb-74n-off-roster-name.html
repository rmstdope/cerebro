cb-74n — what Cerebro says when the navigator asks for a name that is not on the roster

Today agents/orchestrator.md says “Implementers are named after X-Men… if the navigator asks for a name that is not an X-Man, say that it will not start rather than trying it.” That reason is wrong: scripts/launch refuses a name for not being on the roster, and the roster is whatever .cerebro/roster.conf declares. The three options below differ in what Cerebro does about it, not only in how it words it. The scene is the same in each: this repository’s roster declares Cyclops, Storm, Wolverine, Rogue, and the navigator asks for a name that is not there.

Chosen by the navigator, 2026-09-08: Option A. B was declined as a new capability with real blast radius (file order is load-bearing; a bad row refuses the whole roster with exit 2) and belongs in its own bead if it is ever wanted. C was declined because making the navigator find out by trying is exactly what the sentence being corrected was written to save them.

Option A — refuse, and name the roster (today’s behaviour, corrected reason) — CHOSEN

you ▸ start Morph on the next planned bead

Cerebro ▸ Morph is not on this project's roster, so `launch Morph` would refuse
          (exit 2) and nothing would start. The implementer names this project
          declares are Cyclops, Storm, Wolverine and Rogue — all four are up.

          If you want an implementer called Morph, add the row to
          .cerebro/roster.conf and commit it; I'll pick the name up on my next
          pass.

Cost: nothing new is built; one sentence changes meaning. Cerebro still refuses before trying, but for the true reason, and it tells you where the list actually lives. The navigator does the edit.

Option B — refuse, and offer to add the name to the roster

you ▸ start Morph on the next planned bead

Cerebro ▸ Morph is not on this project's roster, so `launch Morph` would refuse
          (exit 2). The declared implementers are Cyclops, Storm, Wolverine and
          Rogue — all four are up.

          I can add Morph to .cerebro/roster.conf as a fifth implementer. That is
          a tracked file, so it is a commit on main and every clone gets it.
          Add it?

you ▸ yes

Cerebro ▸ Added `Morph  implementer` to .cerebro/roster.conf and committed it
          (roster: add Morph as an implementer). The fleet view will show the row
          on its next read. I cannot start a session — run
          `.claude/cerebro/scripts/launch Morph`, or press s on its row.

Cost: a new capability for Cerebro — it edits and commits a tracked declaration. Order is load-bearing in that file (the orchestrator takes implementer names in file order), and a bad row refuses the whole roster with exit 2, so this is a write with real blast radius. It also needs its own rules: where the row goes, whether it carries standby, and what happens on a dirty checkout.

Option C — do not pre-judge; run it and report what happened

you ▸ start Morph on the next planned bead

Cerebro ▸ I cannot start a session — that is yours or the fleet view's. If you run
          `.claude/cerebro/scripts/launch Morph` it will answer for itself; on this
          roster I expect it to refuse, since the declared implementers are
          Cyclops, Storm, Wolverine and Rogue.

Cost: the least prose, and it never asserts a fence that a consumer's own roster might not have. But it makes the navigator find out by trying, which is exactly what the sentence being removed was written to save them.

Unchanged in all three — the ordinary “start another builder” answer

you ▸ start another builder

Cerebro ▸ Storm and Wolverine are up. The next unused implementer name this
          project declares is Rogue — run `.claude/cerebro/scripts/launch Rogue`,
          or press s on its row in the fleet view.

Today this paragraph reads “when you pick a new X-Man name”. In every option it becomes “the next unused implementer name this project declares”, which is the same act with a true reason. The built-in default table in scripts/roster stays X-Men and is not touched by this bead.
