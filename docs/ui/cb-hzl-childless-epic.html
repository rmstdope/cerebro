cb-hzl — where a childless epic shows up, and how it reads

Today both views skip every epic before any bucket is considered. That is right for an epic with children — it is bookkeeping over them, and listing it beside them double-counts the same work. It is wrong for an epic with no children: nobody has broken it down yet, so it is exactly as unplanned as any other unplanned bead — and because the Unplanned bucket also feeds the planner trigger, no planner is ever started for it. It is not merely unseen; it is unreachable.

5. Question 2 — does a closed childless epic reach Psylocke?

The uniform rule ("a childless epic is an ordinary bead") sends a closed one to Merged, unverified, which is the verifier's queue and her start trigger. No epic on this board is childless today, so this is about what happens later.

6. The consequence of "uniform", found while planning

The Merged, unverified section is the verifier's trigger, but her own work list is a different query — scripts/work-beads --status closed, which excludes every epic outright. Left alone, a closed childless epic would start Psylocke, show her nothing, and sit in that section for ever. So "uniform" means work-beads learns the same rule: an epic is real work exactly while it has no children, asked of bd children per epic, which is what scripts/sweep-epics.sh already does. Epics are rare enough in a closed-since-yesterday list that the extra call costs nothing.

Nothing about the screen changes here — this is what the chosen answer commits to underneath it. Say so if that price is not worth §5's first block, and the open-only rule is the alternative.
