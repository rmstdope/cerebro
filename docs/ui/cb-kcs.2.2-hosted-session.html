The hosted session, as chosen

This is what cb-kcs.2.2 builds: a real agent CLI running in a pty, drawn in the Session pane, taking the navigator's keys. It refines docs/ui/cb-kcs.2-split-console.html, which settled the split, the three-stop focus cycle, Shift-Tab as the only way out of a session, ten thousand retained lines and the focused-session header. Agreed with the navigator over three rounds on 2026-09-01.

Two spellings in the earlier mockup are superseded here, and both were inconsistencies rather than choices:

  • Shift-Tab from a focused session focuses Work, not Fleet — the plain reverse of Tab, with no exception to remember.
  • The Session pane's dim title hint is fixed per session state and no longer varies with which other pane happens to be focused.

Nothing a navigator can press starts a session in this increment. The screens below are reachable from test code alone; s arrives with cb-kcs.2.3.

KeyWhat happens
Every printable character, Enter, Tab, Backspace, Esc, Ctrl-C, the arrows, Home/End, PgUp/PgDn, Insert/Delete, F1–F4sent to the child
Shift-Tabheld back — leaves the session, focusing Work. The child can never receive it.
Anything with no mapping — F5–F12, keypad keys, exotic modifier combinationsdropped in silence. Nothing happens and nothing is said.

A short pane means a short agent

The child is told the pane's real inner size — never a floor of 80×24 with the pane as a window onto it. A window would mean a live session that scrolls, which contradicts every key going to the child, and it would hide from the navigator that they have made the pane too small to work in.
