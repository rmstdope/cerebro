cb-3m0 — the gap between two starts of one role, declared by the project instead of by whoever opened Emacs

Today cerebro-role-start-spacing is a defcustom in emacs/cerebro.el, defaulting to (("planner" . 30) ("implementer" . 30)). It travels to no clone. Question 1 is the shape of the line a navigator writes in .cerebro/project.conf; question 2 is what the fleet view does with a line it cannot read. Everything below is the same file, the same fleet, only the declaration differing.

Option A — one key, per-role pairs on the line

# Seconds between two starts of one role. A role two agents hold answers the
# same condition for both at once; this is the gap that stops them racing.
role_start_spacing  planner:45 implementer:30
Mirrors the defcustom's own shape one-for-one, and a role left off the line is never spaced — the existing "one holder cannot collide with itself" opt-out survives verbatim. Costs a pair parser in elisp (split-string on space, then on :) and a second thing that can be malformed: the line, or one pair in it.

Declaring only the one that is wrong here, leaving implementers on the built-in 30:

role_start_spacing  planner:45
Note the trap: that line does not mean "implementer unchanged" unless the plan says so. Two readings — the line replaces the whole alist (implementers then never spaced), or it overlays it (implementers stay at 30). Whichever is chosen has to be written on the line above it in every consumer's file.

Option B — one key per role

# Seconds between two starts of one role, one key per role. A role with no key
# here keeps the built-in gap; a role only one agent holds is never spaced at all.
role_start_spacing_planner      45
role_start_spacing_implementer  30
Nothing to parse — project-conf role_start_spacing_planner returns a number or nothing, exactly like every other key in the file. Overlay is the only possible reading, so the trap in Option A cannot arise. Costs one project-conf fork per role on the roster at buffer creation (three roles here, once per M-x cerebro), and a key namespace that grows with the roster.

Declaring only the planner:

role_start_spacing_planner      45
Implementers keep 30, unambiguously.

Option C — one number for the whole fleet

# Seconds between two starts of one role. Only roles two or more agents hold
# are ever spaced, so this number is only ever felt by the planners here.
role_start_spacing  45
The smallest thing that answers the bead: one key, one integer, no parser, no per-role table. It is nearly the same behaviour today, because cerebro--role-peers already returns nothing for a single-holder role, so verifier, architect, reviewer and orchestrator are unspaced whatever the number says. What it gives up: a project can no longer set one role's gap without moving the other's, and can no longer say "space the planners, never space the implementers" — that opt-out becomes impossible for a multi-held role.

Question 2 — role_start_spacing soon: a value that is not a positive integer

Option R — refuse, the way a bad roster row refuses

M-x cerebro
cerebro: project.conf: role_start_spacing must be a whole number of seconds, not "soon"
No fleet is drawn at all, and the line is also written to errors.jsonl. Matches cerebro--fleet, whose docstring says an empty fleet drawn in silence is the one outcome that looks like it is working. Cost: a typo in one optional key stops the navigator seeing their fleet.

Option F — fall back, and say so once

M-x cerebro
cerebro: project.conf: role_start_spacing is not a number ("soon"); using the built-in 30s
Agent          Role          State      Bead       Bead/Phase
● Xavier         planner       plan       cb-3m0     12s 12s
◌ Beast          planner       standby               → buffer < 4
The fleet comes up on the built-in number, and the complaint is in errors.jsonl where it outlives the echo area. Matches project-conf's own rule, whose header says it never fails on a bad or absent key because its callers run under set -euo pipefail. Cost: a fleet running on a number nobody declared, which is exactly the state this bead exists to end — mitigated only by the line above.

Not in this bead either way: cerebro-wake-intervals, the other number that decides when a role starts. It has the same "set in one navigator's Emacs" problem and is deliberately left alone here — one reader into cerebro.el is the increment; a second key riding on it is a second argument. Also not assumed either way: whether the fleet view's own autostart, which brought three implementers up in one second, should be spaced at all. Forge's bead says so explicitly and it stays a separate question.

Question 3 — role_start_spacing_planner 0

Option Z — 0 is legal, and means "never space this role"

# This project's planners label their candidate before they research, so two
# starting together costs nothing. Let them start on the same tick.
role_start_spacing_planner  0
Falls out of the existing predicate for free: now - started < 0 is never true, so a zero declares "no gap" with no new code. It is the only way a project can opt a two-holder role out of spacing once the per-role key exists, and it is a real position — a fleet whose planners took their label before researching would want it. A negative number is still malformed.
(no line — 0 is a declaration like any other)

Option N — 0 is malformed, like -5 or soon

role_start_spacing_planner  0
cerebro: project.conf: role_start_spacing_planner is not a positive number of seconds ("0"); using the built-in 30s
Treats a zero as a slip of the finger rather than an intention. Cost: a project that genuinely wants two planners starting on one tick has no way to say so, and the fleet quietly ignores the line it wrote.

Question 4 — a navigator who has set the defcustom in their own init

Option P — the project always wins

;; ~/.emacs.d/init.el
(setq cerebro-role-start-spacing '(("planner" . 90)))
# .cerebro/project.conf
role_start_spacing_planner  45
The planners are spaced 45s. The defcustom is the fallback for a role the project says nothing about, and nothing else — which is what the bead asks for, and what makes every clone of the project run the same fleet. Cost: a navigator's own setting is silently overridden for a declared role.

Option M — the navigator's own setting wins

;; ~/.emacs.d/init.el
(setq cerebro-role-start-spacing '(("planner" . 90)))
# .cerebro/project.conf
role_start_spacing_planner  45
The planners are spaced 90s. Costs a way to tell "the navigator set this" from "this is the built-in default", which Emacs does not make cheap, and gives back the thing the bead complains about: the number that decides whether two planners race is again set in one navigator's Emacs.
