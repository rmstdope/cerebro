Every screen below is rendered from this machine’s real .cerebro/state/decisions*.jsonl and transitions.jsonl, at 13:20 on 2026-09-04. Nothing here is committed.

The four questions the bead names

QuestionWhere the answer already is
No-op passes — a session that started, ended its pass and never held a bead transitions.jsonl: a session (one from:null to the next) whose every line has bead:null and whose last state is waiting
Rows started past a ceiling — a name the view keeps restarting decisions.jsonl: start events per agent in the window
Asking > 1h scripts/fleet-history --json: an open interval with state:"asking"
Names disarmed or given up on decisions.jsonl: give-up, disarm-all, retire

Nothing new has to be logged. All three shapes below read the same four facts; they differ only in what reaches the navigator’s terminal.

Option A — findings only, silent when healthy

The house format of scripts/tracked-links and scripts/four-eye-sync: one line per finding, nothing at all when there is nothing to say, exit 1 when there is. A cron or a gate could run it.

$ .claude/cerebro/scripts/fleet-health
churn:     Xavier started 15 times in 24h (ceiling 8)
churn:     Cyclops started 9 times in 24h (ceiling 8)
no-op:     Storm 5 passes held no bead (of 8)
no-op:     Cyclops 3 passes held no bead (of 9)
no-op:     Wolverine 2 passes held no bead (of 4)
asking:    Psylocke asking 74m on cb-5kk — nobody has answered
$ echo $?
1

And on a healthy fleet:

$ .claude/cerebro/scripts/fleet-health
$ echo $?
0
Cheap to read, and it is the one shape that can be wired into something. It cannot answer “is the fleet fine?” — silence and a crashed script look the same, and the numbers that are within the ceiling are never shown, so you cannot see a fleet drifting towards one.

Scans like the fleet view itself, and “which name” is the first thing you read. The four questions get compressed into columns, so disarmed or given up on becomes a yes/no rather than the event and its reason.

What is the same in all three

  • One command, bash, reading only files that already exist. No bd, no git, no network.
  • --since in fleet-history’s own spelling (90m, 24h, 7d), defaulting to 24h.
  • --json printing the same facts as an object, for anything that wants to ask a different question.
  • It fails loudly — non-zero, a line on stderr, nothing on stdout — when a log is missing or a line will not parse, so “all clear” can never be a broken query. That is fleet-history’s rule.
