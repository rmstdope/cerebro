cb-ykz.2 — the surface the navigator approved, 2026-09-04

Two rounds. This file is the specification for how a stopped session reads on its row, in both fleet views. Where this file and the bead's plan disagree, this file is right. It specifies appearance only: supervision still does nothing about a stuck row — that is cb-ykz.3, and what to do about a stuck implementer, which holds a claim, a worktree and possibly an open pull request, is its own interview.

The fact behind all of it is cb-ykz.1's: a Stop hook stamps turn_ended into the state file, and every agent-state write clears it. A row is stuck when its state is working, its turn has ended, and that has stood past the ceiling.

1. What was wrong

A session that writes working and then ends its turn without writing waiting sits as working for hours, drawn exactly like a row doing real work. Six observed stretches of five to thirteen hours; each was noticed half a day later, if at all.

4. The narrow pane, and the correction chosen — C2

Round one's Ratatui mockup was wrong, and was corrected to the navigator in round two. On any screen 100 cells or wider the Fleet pane is a fixed 40-cell left column — below the 64 that the ROLE and FOR columns need — so the FOR column is not drawn in the TUI's ordinary layout, and variant C would have been invisible exactly where the navigator looks.

Why the BEAD cell. It already stands aside for a standby row's trigger (→ buffer<4, blue) and a dead row's exit verdict (red). This is that same rule with a fourth thing it can be, and it is the one cell in a 40-cell pane wide enough for a sentence. It costs the bead id while the row is stuck; RET and the Work pane still have it. The column must be sized for it — stuck 11h30 is eleven cells where the column's floor is ten.

Rejected in round two. The red glyph alone in the narrow pane — nothing given up, but no duration without widening the terminal. The STATE cell saying stuck — it draws one condition two different ways depending on pane width and loses the phase word.

5. The rules the row obeys

The glyph is ✗ (U+2717), red, in both views. Red ! was in every round-one mockup and is already RowState::Invalid in the Ratatui view — a roster line that would not parse. Sharing it, and keeping the green ● and letting the red text carry the signal alone, were both declined: the vocabulary stays one glyph per condition, which is the rule the existing set follows and has paid for twice.

stuck — a glyph of its own
✗ Wolverine    ci          stuck 8h49

The ceiling is 30 minutes, one number for every role and phase. What it has to separate: an implementer waiting on its own review sub-agent legitimately ends its turn — the one documented exception to the never-end-a-turn rule — and those waits are minutes, where every observed stuck stretch was five hours or more. Thirty minutes is an order of magnitude under the shortest of them and well over any observed review wait. Sixty minutes and a per-phase table were both offered; the single knob was chosen.

Only a working row is ever stuck. An asking row was offered and declined: it is already bold with a gold ? and is a question waiting for the navigator rather than a session that is never coming back — and an implementer's unanswered question is already nudged on its own timeout. Every other state has no turn to have ended.

Row and log only. One stuck line goes into decisions.jsonl per occurrence — not per tick — carrying the phase and how long it has stood. A Sweeps-style finding in the Work pane was offered and declined: findings, and any action at all, belong to cb-ykz.3. A read-only view draws the red row and writes no line, because looking at a fleet is not supervising it.
